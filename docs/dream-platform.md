# Dream Platform

Dream Platform is the local development infrastructure shared by the projects
developed on this workstation. It lives in its own repository and Compose
projects; application repositories consume its shared networks instead of
copying platform services into their own Compose files.

The platform repository contains the operator runbooks and service definitions.
The most relevant references there are:

- `docs/architecture.md` — topology, networks and persistence;
- `docs/getting-started.md` — first-time bootstrap;
- `docs/integrations/application-services.md` — application integration rules;
- `docs/services/mailpit.md` — development SMTP and inbox;
- `scripts/bootstrap-networks.sh` — shared network creation.

## Local platform topology

| Component | Responsibility | Shared boundary |
| --- | --- | --- |
| Traefik | HTTPS ingress for platform-routed applications | `dream_edge` |
| Authentik | Local SSO and identity provider | `dream_edge`, `dream_sso`, `dream_authentik_private` |
| Mailpit | Development SMTP sandbox and inbox | `dream_edge`, `dream_mail` |
| Gatus | Platform health dashboard | `dream_edge` |
| whoami | Disposable routing and forwarded-header check | `dream_edge` |

The platform services are separate Compose projects so that restarting one
service does not recreate the others. Persistent platform state belongs to the
Dream Platform checkout and is not part of an application repository.

## Shared Docker networks

These networks are created by Dream Platform and are external dependencies for
application Compose files:

| Network | Visibility | Purpose |
| --- | --- | --- |
| `dream_edge` | public bridge | Traefik HTTPS ingress and routed services |
| `dream_sso` | internal bridge | Authentik-facing application connectivity |
| `dream_mail` | internal bridge | SMTP connectivity to Mailpit |
| `dream_authentik_private` | internal bridge | Authentik server, worker and database isolation |

The network names can be overridden in Dream Platform's `.env`, but an
application must use the resulting names rather than assuming a Compose-local
network. The network bootstrap is idempotent:

```bash
./scripts/bootstrap-networks.sh
```

## Mailpit integration

Mailpit is intentionally not duplicated by application projects. Connect an
application service to the external `dream_mail` network and configure:

```text
SMTP host: mailpit
SMTP port: 1025
```

The `mailpit` hostname is Docker service discovery on `dream_mail`; it is not a
public DNS name. The browser inbox is exposed by the platform edge at the
Mailpit hostname configured by the platform operator.

Mailpit accepts development credentials and stores messages in the platform's
ignored runtime state. Never use this sandbox as a production SMTP service.

## Cartridge Store integration

The Cartridge Store supports two local edge modes. The default Compose file
contains a standalone Nginx edge. The Dream Platform override delegates Store
and API ingress to the shared Traefik instance instead.

Start the Dream Platform mode with:

```bash
docker compose \
  --env-file /path/to/dream-platform/.env \
  -f docker-compose.yml \
  -f docker-compose.dream-platform.yml \
  up -d --build backend next docs
```

In this mode:

- `backend`, `next` and `docs` join `dream_edge` and receive Traefik labels;
- `docs` owns the higher-priority `store.prg32.test/docs` route and runs
  Fumadocs independently from the Store UI;
- only `backend` also joins `dream_mail`;
- the local Nginx service is assigned the `standalone` profile and is not started;
- Traefik continues to own host ports 80 and 443.

The backend's shared Mailpit boundary is:

```yaml
networks:
  mail:
    name: dream_mail
    external: true
```

Only the backend joins `dream_mail`. The repository does not create a second
Mailpit container.

The standalone application edge uses:

- `store.prg32.test` for Next.js;
- `api.prg32.test` for Fastify and WebSocket traffic;
- local TLS generated by `deploy/local/setup-tls.sh`.

In standalone mode, Nginx owns ports 80 and 443 and Dream Platform Traefik must
not also bind them. In Dream Platform mode, leave Traefik running and do not
start the Nginx service.

For a normal standalone start:

```bash
./deploy/local/setup-tls.sh
docker compose up -d --build
```

If the shared platform is not running, create its networks and start the
Mailpit project from the Dream Platform checkout first. The application stack
will otherwise fail fast because `dream_mail` is an external network.

## Local-only boundary

The `.prg32.test` hosts, dnsmasq/Pawxy mapping, mkcert certificates and Docker
network names are development conveniences. They must not be treated as
production origins. A production deployment needs registered DNS, production
TLS, explicit public origins, cookie policy and a real SMTP provider.
