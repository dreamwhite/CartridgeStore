# M3 — Read-Only API Parity Report

Date: 2026-10-12
Status: **complete for the approved read-only scope**

## Outcome

Fastify now serves the existing public discovery, catalog, media, colophon,
and binary download routes in an isolated read-only implementation. Flask
remains the public API owner and sole writer. No authentication, publishing,
metrics, scores, WebSocket, or frontend route was migrated.

The differential fixture is generated by
`tests/compatibility/generate_m3_oracle.py` from the actual Flask routes and
synthetic PRG32 binaries. `backend/tests/catalog.test.ts` writes the same
fixture into a temporary store and compares Fastify injection responses with
that Flask oracle, including raw binary bytes.

## Implemented route inventory

The following routes existed in Flask and are implemented in Fastify. There
was no separate public version endpoint; version selection remains a query
parameter on detail, media, colophon, and download routes.

| Method/path | Query parameters | Auth | Success | Response and cache behavior | Side effects |
| --- | --- | --- | --- | --- | --- |
| `GET /.well-known/prg32-store.json` | none | Public | `200` | `application/json`; discovery ABI, service URLs, roles, version, and auth flag; no explicit cache header | Flask reads settings; Fastify performs at most a read-only `store_settings` lookup |
| `GET /api/games` | `q`, `search`, `page`, `per_page`, `limit` | Public | `200` | `application/json`; stable `ok`, `games`, and `pagination` fields; title ordering and pagination preserved | None |
| `GET /api/games/<game_id>` | `version` | Public | `200` | `application/json` with `ok` and `game`; selected/latest version and architecture arrays preserved | None |
| `GET /api/games/<game_id>/icon` | `version`, `architecture` | Public | `200` | Raw bytes; `image/png` or `image/jpeg`; `Content-Length`; no explicit cache header | None |
| `GET /api/games/<game_id>/screenshot` | `version`, `architecture` | Public | `200` | Raw bytes; `image/png` or `image/jpeg`; `Content-Length`; no explicit cache header | None |
| `GET /api/games/<game_id>/colophon` | `version`, `architecture` | Public | `200` | `application/json` with `ok` and colophon ABI | None |
| `GET /api/games/<game_id>/download` | `version`, `architecture` | Public | `200`, `206`, or `304` | Streamed `.prg32` bytes; `application/vnd.prg32.cartridge`; attachment filename; length, last-modified, `no-cache`, ETag, byte ranges | Flask inserts `download_events`; Fastify intentionally does not |

Invalid game IDs, versions, architectures, missing variants, missing media,
invalid metadata trailers, and unsafe paths use the existing API envelope:
`400`, `{"ok":false,"error":"invalid request","code":"invalid_request"}`.

The Flask download route also supports conditional requests and byte ranges.
Fastify preserves `304`, `206`, `Content-Range`, `Accept-Ranges`, and the
Werkzeug-compatible file ETag algorithm. ETag values include the absolute
file path by Flask design, so exact ETag strings are path-dependent between
separate processes; the fixture verifies presence and conditional behavior,
while the same-file algorithm is implemented for a shared deployment path.

## JSON serialization comparison

Fastify responses use the existing Python-compatible compact JSON serializer:
keys are recursively sorted, arrays retain order, and the response ends with
the newline emitted by Flask `jsonify`. The oracle compares raw JSON response
bytes for discovery, listing, detail, colophon, and error envelopes. This
avoids accepting a merely equivalent object with changed field ordering or
omitted legacy fields.

## Binary and firmware compatibility evidence

The synthetic fixture contains valid PRG2 payloads with PRG32 metadata
trailers, PNG icon bytes, JPEG screenshot bytes, colophon data, and both
`esp32c6` and `qemu` variants. The test verifies:

- exact full-file bytes for a `qemu` download;
- exact SHA-256 digest;
- default architecture selection preferring `esp32c6`;
- architecture-specific filename and MIME;
- icon/screenshot extraction without rewriting the cartridge;
- missing architecture/version/media errors;
- truncated/corrupt trailer rejection for media parsing while downloads
  remain byte-serving operations, matching Flask's route separation;
- byte-range and conditional download behavior.

The existing Flask firmware contract tests in `tests/test_api_contracts.py`
continue to cover the same discovery ABI, architecture identifiers, PRG2
magic, metadata markers, and synthetic download hashes. No firmware source or
companion repository was modified. A physical ESP32-C6 network smoke test was
not run; that remains operational evidence for the later cutover.

## Filesystem safety and read-only guarantees

`backend/src/catalog/catalog.ts` and the route layer:

- validate game IDs and versions using the existing Flask-compatible grammar;
- resolve index filenames beneath the configured store root;
- resolve both `index.json` and variant files through `realpath`, rejecting
  symlink escapes;
- reject missing/non-regular files before opening them;
- stream full and ranged downloads with `fs.createReadStream`;
- read only the requested media cartridge for icon/screenshot/colophon
  extraction and never rewrite the binary;
- never create directories, index files, cartridge files, or database files;
- do not parse or modify the SQLite database for catalog/media/download;
- return stable generic errors without exposing filesystem paths.

The Fastify test uses a missing database path and verifies it remains absent,
tests `../` traversal and an outside-root symlink, snapshots the store before
and after requests, and verifies the outside file is unchanged.

## Flask download side effects

The existing Flask route calls `record_download` before `send_file`. It hashes
the remote address, stores the optional authenticated user ID and truncated
User-Agent, and commits a row to `download_events`. The generated Flask oracle
performed the successful, conditional, and range requests and observed five
download-event rows.

Fastify M3 deliberately does not reproduce that write. Its SQLite manager is
read-only and the catalog routes do not call `download_events`. This is a
compatible intentional difference for the parallel read-only phase, not a
claim of operational side-effect parity. Before a future route cutover, the
team must choose one writer/side-effect owner and define reconciliation or
explicitly retain Flask download tracking.

## Unresolved incompatibilities and risks

1. Exact Flask ETag strings contain the absolute file path and therefore vary
   across separate container roots. Fastify implements the same Werkzeug-style
   calculation, but a deployment must align paths or approve a content-based
   ETag change before claiming byte-for-byte header parity.
2. Fastify has no public route ownership, authentication/session support, or
   download-event writer. Flask must remain routed publicly.
3. The M3 parser covers the PRG2 header, optional audio block, metadata TLV,
   icon, screenshot, and colophon required by these routes; broader PRG32
   binary validation and unknown-block tooling remain future work.
4. A live ESP32-C6/QEMU client smoke test through Traefik was not run. The
   synthetic firmware contract fixtures passed.
5. The Fastify media route reads the cartridge to extract trailer assets;
   large binary download paths are streamed, but media extraction should be
   profiled before production routing.

These are explicit migration risks, not hidden parity assumptions.

## M4 prerequisites and recommendation

Before M4 authentication migration or any cutover:

- keep Flask as the public owner while auth/session/token compatibility is
  implemented and tested;
- decide whether download-event tracking remains Flask-owned or moves with a
  single controlled writer;
- run a Traefik-origin smoke test for discovery, catalog, ranges, conditional
  requests, and WebSocket preservation;
- perform a physical/firmware client smoke test and record the exact host,
  scheme, port, and architecture behavior;
- resolve the deployment ETag path issue or approve an explicit versioned
  cache-validator policy;
- add golden malformed/truncated PRG32 fixtures and profile media extraction;
- do not enable public Fastify routing until the above evidence and rollback
  procedure are accepted.

M3 stops here. M4, authentication migration, and public traffic cutover were
not started.
